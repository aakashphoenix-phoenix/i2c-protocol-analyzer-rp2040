## Measured (analyzer = bus truth)

- 1168 packets in 70 s, 16 turns. Sequence on the bus: M1, M2, M1, M2, ... (16 of 16 alternate).
- Every turn: RTC 0x68 (`w1 r16`), then BMP280 0x76 (`w1 r6`, plus chip ID `r1` and calibration `r24` every second turn), then
  OLED 0x3C (6 window commands + 64 data writes). 72 or 74 transfers per turn.
- Idle bus between turns (last STOP to next START): min 4.0003 s, median 4.0008 s, max 4.0014 s (15 gaps).
- Turn duration: Master 1 144.0–148.8 ms, Master 2 146.7–150.9 ms.
- ACK 19368, raw NACK 48 = 48 `read[final]` end-of-read NACKs with a captured STOP, 0 unexpected, 0 unverified.
- Analyzer: 0 lost records, 0 DMA/queue drops, 0 stream gaps, 0 `mid_byte_end`. SCL median 94.57 kHz.
- Controllers over 76 s: Master 1 `txn_ok` +658, Master 2 +656; `addr_nack`, `data_nack`, `arb_lost`, `retries`,
  `gave_up`, `busy_waits`, `timeouts`, `recoveries` all 0 for both. Every `turn_end` reports `rtc ok`, `bmp ok`, `oled ok`.
- Controller-reported `idle_before_us`: 4000037–4000910 µs.

## GUI fixes found with this capture

- `communication/master_protocol.py` rejected `turn_start` / `turn_end` / `peer_absent`: now validated and accepted.
- Clock alignment (`analysis/multi_master.py`) without the live USB-arrival prior:
  - candidate offsets must map the triggering transfer within 1 s of the newest packet (whole-cycle and half-cycle shifts
    of identical turns explained the data equally well);
  - a packet already claimed by another master's telemetry no longer counts as a hit;
  - rival offsets are compared by signature-weighted hits (a one-transfer slip inside 70 identical OLED writes was
    rejecting the true offset);
  - crystal drift is modelled (offset + slope): measured -30 ppm (Master 1) and +13 ppm (Master 2), the same as the
    2026-11-15 fit (-28.6 / +13.6 ppm). Transfers from before the lock no longer reset a correct lock.
  Result: 1168/1168 packets attributed by telemetry (584 / 584) at any replay chunk size; the 2026-11-15 capture stays
  2419/2419 (2295 / 124).
