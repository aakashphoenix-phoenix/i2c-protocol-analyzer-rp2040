# AT24C32 / bus NACK investigation — hardware measurement, 2026-11-09

Procedure, identical before and after: analyzer on COM28, 60 s live capture with
`python -X utf8 tools/nack_phase_report.py --port COM28 --seconds 60 --save <file>.jsonl`.
Controller identity was checked on COM32 with `tools/read_controller_log.py COM32 12`.
Raw records are kept in `before.jsonl` / `after.jsonl`; full per-address reports are in `before_all.txt` / `after_all.txt`.

## Change between runs
The controller was flashed with `I2C/I2C/build/I2C.uf2`, built 2026-11-09 09:56 from the current `I2C.c` (`SCAN_PERIOD_MS 0`).
Flashing used a 1200-baud reset on COM32 only, so the analyzer on COM28 was never touched.

- **Before:** controller printed `Bus scan:` every 5 s and did not accept `SCL?`.
- **After:** no scan; answers `SCL?` with `{"type":"scl_config",...,"applied_hz":100000}`.

## 0x57 (AT24C32)
- **Before:** 12 transactions, each `S AF(R) A FF N P`. The EEPROM ACKed its address 12/12. All 12 NACKs were the controller's normal end-of-read NACK. The EEPROM itself produced 0 NACKs.
- **After:** 0 transactions. Nothing in the firmware addresses the EEPROM, so this run says nothing about whether it works.

## Other findings
- The remaining 372 NACKs are all controller end-of-read NACKs: 0x68 ×60 and 0x76 ×312. RTC reads are now 16 bytes (registers 0x00–0x0F).
- **DS3231:** the new firmware reports the oscillator-stop flag (OSF) as set. The year-2179 date shown before came from an RTC whose oscillator had stopped, so its time is not valid until it is set again.
